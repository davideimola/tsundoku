# Hosting and reachability

**Researched:** 2026-08-28 · **No recommendation is made here.** This lays out the facts for a human to decide between hosting the database/app or exposing the home Kubernetes cluster.

## How to read this

- Every claim is traced to the vendor's own docs, pricing page, status page, or changelog. Where a fetch turned up only third-party aggregator numbers and no first-party page confirmed them, that is stated inline rather than silently promoted into a fact.
- Prices and policies are as observed on **2026-08-28** — record next to each citation, since these change often.
- Where a vendor's own wording is vague (no exact number), the vague wording is quoted verbatim rather than resolved into a guessed number.

---

## Answer

Supabase's own docs are unambiguous and confirm the complaint: **"Free projects are paused after 1 week of inactivity"** ([pricing](https://supabase.com/pricing), 2026-08-28), with the underlying rule stated as **"We may pause applications on the Free Plan that exhibit low activity in a 7-day period to save on server resources"** ([going-into-prod](https://supabase.com/docs/guides/deployment/going-into-prod), 2026-08-28). A paused project must be manually resumed from the dashboard, has a 1-year restore window before Supabase Studio can no longer bring it back, and the only way to guarantee no pausing is the $25/mo Pro plan (**"Upgrade to Pro to guarantee that we won't pause your project for inactivity"**). Every hosted-Postgres vendor surveyed below either scales-to-zero (Neon, Xata, CockroachDB Basic — resuming automatically and fast, no manual action, no data loss) or has an opt-in/paid path to a genuinely always-on instance for roughly $5–40/month (Aiven Developer Tier $5, Render Basic-256mb $6, Fly Managed Postgres Basic $38, DigitalOcean $15) — none of which is Supabase's own cheapest paid tier's headline behavior of simply never pausing at all once you're on Pro. For reachability: Tailscale Funnel is free on every plan (including Personal/free) but is locked to Tailscale-assigned `*.ts.net` hostnames, only ports 443/8443/10000, and has no documented hard timeout on response duration in its own docs. Cloudflare Tunnel is free and usable with a real custom domain, integrates with Kubernetes via an official deployment guide, but Cloudflare's own connection-limits table documents a **125-second Proxy Read Timeout** on the Cloudflare-to-origin hop that is **not configurable except for Enterprise zones** — a real risk for MCP's streamable-HTTP transport if a tool call goes silent that long. Both mechanisms are otherwise well-documented, free options for exposing one Kubernetes service publicly without opening router ports.

### Caveats worth reading in full

- **Supabase deletion timeline is genuinely fuzzy.** The docs give a 1-year Studio-restore window (**"Once the project is paused, there is a 1-year window to restore the project on the platform from within Supabase Studio"**) and a separate troubleshooting page confirms **"Projects paused for more than 1 year can no longer be restored through Supabase Studio"** — but manual recovery via downloaded backups may still be possible before actual deletion. No page states the exact day data is irrecoverably deleted. ([free-project-pausing](https://supabase.com/docs/guides/platform/free-project-pausing), [restore-project-after-90-days-pause](https://supabase.com/docs/guides/troubleshooting/restore-project-after-90-days-pause))
- **Render's free Postgres clock runs even if the app never goes idle** — it is 30 days from creation date, not 30 days of inactivity, so a "keep it alive" script does not help; only upgrading to a paid plan before day 30 avoids the 14-day-grace-then-delete sequence. ([render.com/docs/free](https://render.com/docs/free))
- **Aiven's 180-day auto-delete is the one clearly-documented true data-loss risk on a nominally "free forever, no time limit" plan** — the free tier says **"There's no time limit when using Aiven for PostgreSQL® free plan"** but also **"Service powers off after a period of inactivity"**, and the powered-off state itself starts a 180-day countdown to permanent deletion. ([free-postgresql-database](https://aiven.io/free-postgresql-database), [service-power-cycle](https://aiven.io/docs/platform/concepts/service-power-cycle))
- **CockroachDB's cheapest non-scale-to-zero tier is not actually cheap** — Standard/Advanced are provisioned-vCPU pricing in the same range as a small VM, and Standard is still labeled "Preview". For a tiny single-user app, Basic's scale-to-zero behavior (free, RU-metered) is likely the practical fit despite not being "always-on" in the strict sense asked for here.
- **Fly.io has two distinct Postgres products** with different idle policies: the newer Managed Postgres (MPG, $38/mo+) documents no pausing at all, while the older, still-supported self-managed "Fly Postgres" has an optional, fixed, non-configurable 1-hour scale-to-zero for its cheapest "Development" configuration.

### B2. Cloudflare Tunnel (cloudflared)

| Fact | Detail | Source |
|---|---|---|
| Cost | Free to use; usable on Cloudflare's free plan | inferred from [get-started docs](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/) — no separate charge for the tunnel connector itself is documented |
| Scope of exposure | Single service or many, per Ingress rule — a named tunnel proxies specific hostnames/paths to specific local services; a "Quick Tunnel" proxies one `localhost` port | [get-started](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/); [Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/do-more-with-tunnels/trycloudflare/) |

| Custom domain vs vendor domain | A persistent named tunnel with a stable hostname needs a domain on Cloudflare DNS. | **Timeout — Cloudflare ↔ origin (this is the one that bites streaming)** | Proxy Idle Timeout: **900s**. **Proxy Read Timeout: 125s**, returns HTTP 524 at the limit, and is documented as **"Yes, for Enterprise zones"** only for configurability — i.e. not adjustable on Free/Pro/Business. Proxy Write Timeout: 30s. HTTP/2 Connection Idle: 900s | [Connection limits](https://developers.cloudflare.com/fundamentals/reference/connection-limits/) |
| WebSocket idle behavior | **"Cloudflare will close a WebSocket connection when no data is transmitted in either direction for a period of time"**; Cloudflare recommends **"implement a client-side heartbeat (ping/pong) mechanism"** to keep long-lived connections alive; Enterprise customers can request custom idle timeout configuration | [WebSockets docs](https://developers.cloudflare.com/network/websockets/) |
| Kubernetes guidance | First-party, documented: run `cloudflared` as **"an adjacent deployment to the application deployments"**, not embedded in app pods, so it can scale independently. Explicit caution: **"We do not recommend using `cloudflared` in autoscaling setups because downscaling (removing replicas) will break existing user connections to that replica"**; replicas are for HA only, **"replicas are strictly for high availability"**, not load balancing | [Kubernetes deployment guide](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/deployment-guides/kubernetes/) |

**Flag for MCP streamable-HTTP specifically:** MCP's streamable-HTTP transport keeps a single HTTP response open and streams chunks (SSE-style) as a tool call runs. Cloudflare's documented **125-second Proxy Read Timeout** between Cloudflare and the origin — non-configurable outside Enterprise — means any gap longer than that with no bytes sent on the response will be killed with a 524. A period ping/keepalive chunk shorter than 125s would work around this, but that is a workaround the MCP server would have to implement, not something free out of the box. No equivalent documented numeric timeout was found for Tailscale Funnel.

ngrok's Kubernetes Operator/Ingress Controller exists (`ngrok.com/docs/k8s/`), but its own docs page did not surface pricing, timeout, or streaming-support details on inspection — not included as a fact-table row per the primary-sources-only rule; flagged in Open questions instead. ## C. The honest trade-off

**Shape 1 — everything hosted.** A managed Postgres (cheapest genuinely always-on options found: Aiven Developer Tier $5/mo, Render Basic-256mb $6/mo, DigitalOcean $15.15/mo, Fly MPG Basic $38/mo, Supabase Pro $25/mo) plus a hosted app platform for the web frontend/MCP server. Money cost is a small, predictable monthly line item (roughly $5–40/mo for the database alone, before an app-hosting bill). Operational risk shifts to the vendor: uptime is the vendor's SLA (where one exists, e.g. DigitalOcean's, which explicitly excludes scheduled maintenance), there is no dependency on home power/internet, but there is vendor lock-in to that provider's specific product (as the Vercel Postgres shutdown-and-migrate-to-Neon precedent shows can happen even to a major platform's own branded product) and a small but real chance of forced pausing/expiry/deletion if the cheapest tier chosen turns out to have hidden inactivity rules (Supabase Free, Render Free, Aiven Free all have exactly this shape) — the fix documented throughout Part A is simply to pay for the tier that says "always-on" or "no idle shutdowns" outright.

**Shape 2 — app and database at home, behind a public tunnel.** Both Tailscale Funnel and Cloudflare Tunnel are free for a single low-traffic service, and Cloudflare Tunnel supports a real custom domain while Tailscale Funnel is limited to a `*.ts.net` vendor hostname. Money cost is close to zero beyond power and the home internet connection already in place. Operational risk is the mirror image of Shape 1: uptime now depends entirely on the home cluster staying powered and connected — multi-week holidays are exactly the scenario where a home ISP outage or a power blip with no one present to reboot anything would take the app down, with no vendor SLA to fall back on. There is no vendor lock-in and no risk of a vendor pausing or deleting the database out from under the owner. The one documented technical risk specific to this shape is Cloudflare's non-configurable 125-second Proxy Read Timeout on streaming responses, which could break a long-idle MCP tool call unless the server sends periodic keepalive data; Tailscale Funnel does not have an equivalent documented limit, but also does not offer a custom domain.

| | Shape 1: hosted | Shape 2: home + tunnel |
|---|---|---|
| Cheapest all-in DB cost/mo | ~$5 (Aiven) – $38 (Fly MPG) | $0 (self-run Postgres on existing hardware) |
| Reachability cost/mo | N/A (same host serves it) | $0 (both tunnels are free for one service) |
| Uptime depends on | Vendor infrastructure + vendor SLA | Home power + home ISP, no SLA |
| Data-loss risk | Only if the cheapest/free tier's inactivity rule is not read carefully (Parts A) | None from a vendor; only from local hardware failure / lack of backups |
| Streaming/MCP risk | None documented for the app-hosting side researched here | Cloudflare Tunnel's 125s proxy read timeout (Enterprise-only to change); none documented for Tailscale Funnel |
| Vendor lock-in | Yes, to whichever platform is chosen | No |

## Open questions

- No vendor doc gives a numeric cold-start latency for Supabase's "Resume project" action.
- No vendor doc states an exact automatic-deletion day-count for a Neon, Xata, Prisma Postgres, or CockroachDB Basic free-tier project that is never touched again (only Supabase's 1-year Studio-restore window and Aiven's 180-day powered-off deletion were found as concrete numbers).
- No numeric bandwidth/fair-use cap was found in Tailscale's own docs for Funnel traffic — only the vague **"non-configurable bandwidth limits"** wording.
- No documented hard timeout on total connection/response duration was found in Tailscale Funnel's own docs (as distinct from Cloudflare's documented 125s/900s/400s figures) — this may mean there genuinely is none, or that it exists but isn't published; not resolved here.
- ngrok's Kubernetes Operator page did not yield pricing, timeout, or SSE/streaming support details on the pages fetched — worth a follow-up look directly at ngrok's pricing and Kubernetes-ingress docs if it becomes a serious contender.
- Fly.io's 2022 blog post claiming a free persistent-volume allowance for self-managed Fly Postgres was not re-confirmed against current (2026) terms and may be superseded; only the 1-hour scale-to-zero mechanic was independently re-verified against current docs.
- Whether Cloudflare's 125-second Proxy Read Timeout is measured per-chunk (i.e., reset by any byte sent, which a keepalive comment/ping would satisfy) or as a hard ceiling on total response duration is not spelled out explicitly on the connection-limits page beyond the table's own terms; the practical fix (send periodic data) is inferred, not quoted from Cloudflare.
